# 源码发布与隐私边界

## 发布内容

发布对象为审查后的当前源码、公开文档、示例配置和程序图标。实际运行需要的数据由用户安装时创建。

禁止随源码发布：真实账号和密码、个人邮箱和电话、聊天和参会记录、录音录像、数据库、云服务密钥、OAuth 密钥、用户 CSV 导出、私人证书、日志、开发者主目录，以及含有这些内容的旧构建产物。

`.env`、`.runtime/`、数据库、证书、日志、SDK 与构建缓存已由忽略规则隔离；忽略规则不能清除已经跟踪或存在于 Git 历史中的文件。安装器会生成随机密码和密钥，不存在可公开复用的演示口令。

## 扫描与导出

```bash
python scripts/release_audit.py
python scripts/release_audit.py --output artifacts/releases/vibemeeting-source.zip
```

扫描对象为 Git 已跟踪且仍存在的文件，以及未被忽略的新文件。工具会拒绝私密文件类型、运行目录、符号链接、路径越界、未审查的二进制文件、图片元数据，以及常见密钥、JWT、邮箱、手机号、内网 IP 和个人主目录路径。

结果只包含文件名、行号与规则，不打印敏感值。发现问题时退出码为 1，禁止生成发布 ZIP。导出不会覆盖已有 ZIP，不会包含 `.git` 或本地运行数据。修改源码后必须重新扫描和导出。

扫描依赖 Git 与 Python 3.10+；完整提取后的源码包需要先建立 Git 仓库，才能再次使用当前扫描入口。

## Git 历史不能随本次清理直接公开

现有 Git 历史含有作者 / 提交者邮箱标识，以及旧文档、缓存与已删除文件。工作区中的替换和 `.gitignore` 不会改变旧提交。这次不重写原仓库历史，不强制推送任何分支。

推荐从通过扫描的 ZIP 解压建立新的发布仓库，使用维护者选择的公开身份或 GitHub noreply 邮箱创建初始提交。原始 `.git` 留作私有开发历史，不复制到新仓库。

如需保留历史公开，应先对全部分支、标签、提交消息、作者信息、Git LFS 对象、子模块、Release 附件和既有 Issues / PR 做独立审查。若发现曾提交真实密钥，先吊销轮换，再处理历史；发布新源码包不会消除既有远端泄漏。

## 人工复核范围

扫描是发布门禁，不能证明任意自由文本或图片像素绝无隐私。发布者仍需核对截图中的昵称、头像、二维码、参会链接、聊天和客户资料；当前发布文档未加入真实会议截图。扫描器不会自动访问远端仓库、Git LFS 或外部链接，也不会认证第三方资源许可。

正式发布前应确认：最终许可证、作者公开联系渠道、第三方署名、当前 ZIP 扫描结果，以及新发布仓库不含旧历史。
